- 此前授权的旧片连续衔接回改已完成并验收：13片／35组主体／43处切镜，见 docs/continuity-retrofit-storyboards.md；原15片／94镜头、时长和实验数据不变，递归已有匹配运动和原30秒机制保留。该轮未开展补码；随后用户已另行授权，按上述新分镜推进。
- 必须先写完整分镜，再编码。每镜头记录叙事目的、初始画面、元素出现／退出时机、Enter / Action / Hold / Exit、实际时长和镜头运动，以及从上一镜头保留的对象／数据与它们的真实生命周期。
- 顺序是：分镜 → 视觉规范 → 实现 → 真实浏览器运行 → 根据截图与运动效果修改 → 再验收。不能以代码检查或静态截图代替真实播放。

## 技术与文件组织

- 使用 HTML 页面与场景结构、CSS 视觉、多个 SVG 图形组件、JavaScript 状态和 GSAP Timeline。禁止把整部动画堆进一个 SVG，禁止退回单图配 SMIL 或固定面板文字轮播。
- 主题入口直接放在实际章节目录 `chapter3/`、`chapter6/`、`chapter8/`、`chapter9/` 等；一个主题一个 `.html` 和主题模块。镜头复杂时可拆主题前缀模块，不再建主题子目录。
- `shared/` 维护唯一的播放器、主题样式和图形／动画工具。新主题复用，不复制七套播放、进度或键盘逻辑。新片可用scene-kit.continuity／mountFilm.buildContinuity的跨镜头层；回改旧构图可用actorContinuity声明真实同一对象的视图，保留原节点／按key保留数组行，旧选择器别名不产生可见副本。状态补丁和移动必须放入对应局部时间线，保证倒拖时按实际时序恢复；不靠onUpdate复制HTML、不可逆回调或克隆节点维持连续。拒绝合并不同PID、文件、物理寄存器或相同key但不同VA的对象。
- `models/` 维护可验证的教学数据模型；渲染和断言使用同一数据，不允许图上的数值与模型各自硬编码后漂移。
- 原始源码分场景维护，静态构建产物供发布。资源全部本地打包，禁止运行时依赖 CDN、远程字体或远程接口；不引入应用后端。
- 目录入口为“站点 → 章节 → 主题 → 独立动画”；动画页面能返回章节。资源和链接必须兼容 GitHub Pages 的项目子路径，不写死域名或站点根目录。

## 视觉语言

- 用户最新确认：画布与页面背景使用纯黑 #000，不用灰蓝渐变或环境光。普通文字默认纯白 #FFF，不能再用低对比灰字当成高级感；结构线可用白／灰。
- 颜色只承担明确语义：蓝色输入源／返回地址、青色目标／当前操作／正常流动，红色错误／异常／禁止状态；不随意给普通说明与标题染色。彩色数据包内可用黑字反显以保证对比。此前近黑渐变、灰蓝正文约定不再生效。
- 新 OS 导读章的内存默认用竖向连续分块数组：高地址在上、低地址在下，注明进程／VA／方向与折叠空洞；磁盘文件单独标文件 offset 向下增加，不混为内存。实际地址与物理示意分开，父子各有独立列。后续涉及内存优先遵循此语法；不为此擅改既有七片。
- 16:9 设计坐标，桌面优先，响应式缩放。中文使用本地 Noto Sans CJK／思源黑体／系统黑体回退；代码、地址和数值使用清晰等宽字体。
- 寄存器／关键对象名应比普通小标签更大、更醒目：1440 设计坐标下寄存器符号约 26px 加粗、普通名词标签约 20–24px、辅助正文约 20px；不连同冗长释义一起挤成小灰字。长实测地址不可截断，应重新安排宽度与留白。
- 留白优先，控制发光与阴影。线条不能穿文字、箭头不能盖数字；避免密集表格、无意义装饰、持续闪烁和无关弹跳。
- 不能所有对象都画成矩形卡片。按语义使用 CPU 引脚、内存页、连续字节带、锁、程序窗口、执行令牌、引用线等原创矢量组件。

## 视频级叙事：强制要求

- 首帧只展示当前镜头所需的基础对象。允许预先创建 DOM，但未来镜头／未来步骤必须有效隐藏，不能仅留在暗背景里。
- 每镜头独立构图，随讲解重组布局。用户最新要求：下一镜头仍需要的内容和数据必须保留，不默认整屏清空再重建；用同一DOM对象的移动、放大与重排衔接，只退出不再需要的部分。可用共享持久层与场景局部层，未来对象仍严格隐藏。禁止一张全景图从头播放到尾；禁止仅用颜色闪烁模拟写入、复制、返回、替换等复杂动作。
- 所有重要操作有可见过程：对象从何处来、经过哪里、何时到达、何时提交状态、造成什么结果。
- 复制／覆盖镜头必须持续标明源、目标的变量名与用途，容量边界不随输入变大；不能只靠运动或颜色让观众猜对象身份。复制保留源内容，写前未知值明确标为未知，不能暗示已清零。
- 使用局部推近、拉远、平移、跟拍或逻辑视角切换。能继承主体的镜头应匹配衔接，其他转场要明确说明对照／重试，不能暗示程序倒退或自动恢复。
- 动作之后留约 1–3 秒理解时间。以已确认的慢速调用栈样片为阅读基准，复杂主题允许更长，不强行每片 30 秒；不能靠只拉长总时长掩盖单步过快。
- 代码只在相关动作附近出现，通常 3–8 行，活动行与图形联动；完整可运行程序单独提供。禁止用大量文字代替运动解释。
- 主要短注贴近对象；底部只放简短辅助字幕、控件与模型边界。避免观众必须反复上下寻找原因和结果。

## 实验数据优先与可核对来源

- 用户已要求“实验代码 → GDB／系统观测 → 数据文件 → 动画”。涉及真实地址、寄存器与栈布局时优先做可复现采集，不凭直觉编造数值或把模型常量包装成实测。
- 每个主题必须明确标为“GDB／实验实测回放”“C／GDB 实验 + 机制模型”或“教学模型”；不同主题不能借用一个已验证 C 示例就一概声称动画数据真实。当前七个既有主题和六节 OS 导读均有完整 C 与实际 GDB／工具证据；栈帧／缓冲区核心数值实测，其余五片将实验事实与机制模型分开。实际完成与限制见 docs/spec.md。
- 完整程序必须可查看／下载，相关代码与真实 GDB 命令／输出必须在实验镜头或可定位的工作台中出现。不能用静态源码附件和一个哈希面板代替程序驱动的讲解，也不能只做一个试点就把多数可实验主题长期留作抽象图。
- 主镜头可省略采集标记、注释和非当前逻辑，但保留真实源行与说明；完整工作台必须展示未删改程序。实验定位与解释性机制定位要分开命名，不能把后者冒充完整逐指令 CPU 录屏。
- 实测主题在 experiments 中提供源码、scripts 中提供采集脚本、traces 中保存采样。记录编译器/GDB、完整参数、ASLR 条件、源码与 ELF SHA-256、采集时间和观测范围。播放静态采样时标为离线回放，不声称网页正在运行 GDB。
- 数值、地址、分配量、源码行号与实际指令来自采样；镜头、箭头与教学速度是解释性设计。初始化前的形参/局部值不能直接当作有效 C 值展示，入口参数先查寄存器。
- 采集或断言失败必须报错，不能回退到手工“预期地址”。支持用户代码前先核对结构、编译参数和可观测性，不自动执行陌生程序。
- GDB 不能直接看到真实 Cache/TLB 的全部硬件状态，也不能仅凭 VA 或 maps 证明 PFN/COW；不可观测部分明确保留模型。浏览器测试独立读取原始采样核对显示值，不能只与渲染器内同一份手写常量比较。

## 教学准确性

- 涉及机器代码默认 Linux x86-64 / SysV / 小端，并标注示意布局与优化假设。返回值、返回地址、当前 rip 分开；普通函数调用不是进程切换或进入内核。
- 缓冲区越界写与递归栈空间耗尽必须区分。越界是 C 未定义行为；模型的预设状态或受控 ELF 的某次实测结果均不能推广为所有编译条件下必然发生的结果。
- TLB 属于 CPU/MMU，缓存翻译和权限；页表是 RAM 中的数据；内核是同一颗 CPU 执行的软件，不是另一块硬件。TLB miss 不等于缺页，Cache miss 也不等于缺页。
- 明确何时查询、何时写回、何时重试、何时回填。阻止的访问不能画成已经写入或已经返回数据。
- fork 的独立地址空间不等于立即复制全部物理页；COW 复制完成后才能改映射并重试写。进程退出与回收、用户映像与内核记录分开。
- 图形尺寸、页号、地址、容量、帧数与教学时钟均说明模型边界。释放不等于清零，相同虚拟地址不等于同一物理页。

- C位运算与整数必须先考虑整型提升及实际运算类型；uint8_t并不保证按8位做~、移位或加法。区分unsigned模运算、unsigned窄化、超范围signed转换与signed算术UB；非法移位／signed溢出若被安全检查拦截，不可显示伪造的计算结果。数学推导逐位揭示不等于实测CPU逐位时钟或C对象分步store；位权横图不是内存地址图。

## 播放控制

- 全部主题提供自动播放、播放／暂停、上一步／下一步、单步讲解、重新播放、可拖动进度条、场景导航和全屏。
- 默认自动播放，结束停留末帧；减少动态效果偏好默认暂停。单步以关键操作完成后的稳定状态为停点，不只是跳整张场景。
- 主 GSAP Timeline 是唯一教学时钟。状态必须可正向／反向／乱序定位，不依赖不可逆回调去增删内容；显式场景 gate 保证仅当前镜头局部层可见；跨镜头仍需使用的共享对象由同一时钟管理生命周期，不随局部root.hidden被清空。
- 进度条与时间显示使用真实播放秒数。拖动冻结动画，释放恢复拖动前状态；首尾夹取，最右端不跳回开头。
- 鼠标、触摸、键盘均可用；Space 播放／暂停，左右键关键步骤；进度条聚焦时左右为 1 秒、Shift 为 5 秒、Home/End 为首尾。
- 隐藏的教学场景也要正确设置无障碍可见性；按钮、进度和状态提供语义。不能宣称 GitHub README 图片模式能运行网页交互。

## 验证、进度与清理

- 每完成一个独立主题或功能，在同次交付更新 `docs/spec.md`：入口、完成内容、剩余范围、实际验证结果。只有完成且通过验证才标已完成。
- 验证模型数值与时序；逐镜头检查初始隐藏、入场、运动、理解停留、退场、前后定位以及精确切换边界。含持久层时，文本／遮挡／运动检查必须同时包含持久层，不只查当前.scene；验证所需DOM身份、值与地址跨边界不变、无透明度闪空、位置连续，并在真实逐帧播放中检查。必须检查光点确实位移，不能仅检测存在某个 SVG。
- 路径运动尽量使用同一 SVG 的局部坐标，避免对 display:none 场景测屏幕矩阵造成路径坍缩。
- 共用播放器修改后回归全部主题：真实时钟冻结／继续、单步停点、前后拖动、首尾、键盘、触摸、重播和完整自动播放。检查所有镜头截图的文本边界、遮挡与留白。
- 构建后在本地实际打开发布产物，同时测试项目子目录前缀，检查章节链接、资源、返回导航无 404。未经用户要求不实际推送或部署远端站点。
- 新版全部通过前不删旧版。清理仅限本项目被替代的 SVG、旧生成器、废弃控制器／测试和旧说明；不动学习代码或本次仍有用的 C 示例。新 OS 导读的 .o/.elf 为显式可下载文件结构证据，不能误当废弃调试产物删除，也不能自动执行。更新旧链接，不能两套架构长期混放。
- 如条件不足，明确未测试项；Chromium 通过不代表 Firefox、Safari、真实移动设备或屏幕阅读器已验证。
- 交付简洁说明入口、改动、验证及未覆盖事项，不以创建文件冒充动画完成。
