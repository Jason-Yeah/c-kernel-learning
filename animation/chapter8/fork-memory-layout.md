## 运行代码

在仓库根目录执行：

```bash
cc -std=c11 -O0 -g -Wall -Wextra -Wpedantic \
  animation/chapter8/fork-memory-demo.c -o /tmp/fork-memory-demo
/tmp/fork-memory-demo

# 额外显示这些对象所在的实际虚拟映射及权限

```

程序依次输出 `PARENT_BEFORE → CHILD_BEFORE → CHILD_AFTER → PARENT_AFTER`。两条管道确保子先完成修改，父再读取，子此时仍存活；不靠 `sleep()` 猜调度。最后父用 `waitpid` 回收子进程。

### 关键片段

```c
/* fork 前建立两种映射，并让页面有实际初始内容。 */
int *private_page = mmap(NULL, page_size, PROT_READ | PROT_WRITE,
                        MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
int *shared_page = mmap(NULL, page_size, PROT_READ | PROT_WRITE,
                       MAP_SHARED | MAP_ANONYMOUS, -1, 0);
*private_page = 40;
*shared_page = 50;

pid_t pid = fork();
if (pid == 0) {
    *private_page = 400;  /* 私有写入：父仍是 40。 */
    *shared_page = 500;   /* 显式共享：父同步后也读到 500。 */
}
/* 此处省略管道、错误处理和 waitpid；完整可运行版本见 .c 文件。 */
```

### 应观察到的值

| 对象 | fork 前／子修改前 | 子修改后 | 父同步后读取 |
| --- | ---: | ---: | ---: |
| `.data` 中的全局变量 | 10 | 100 | 10 |
| `.bss` 中的零初始化全局变量 | 0 | 200 | 0 |
| 自动局部变量（示例用户栈） | 20 | 200 | 20 |
| `malloc` 得到的对象 | 30 | 300 | 30 |
| 私有匿名页 `MAP_PRIVATE` | 40 | 400 | 40 |
| 共享匿名页 `MAP_SHARED` | 50 | 500 | **500** |

同一次 fork 中，父子打印的相应对象地址相同，但数值可以不同：地址是**虚拟地址**，需要在各自地址空间中解释。下一次运行时，地址可能因 ASLR 等因素改变。只读常量仍为 `read-only`，示例不尝试写只读区域。

## 动画中的八个镜头

新增 **C 程序与 GDB，0～12 秒**：实际 PID、相同 VA 与私有／共享值，工作台可查看六类对象的完整观测。以下七镜头为原机制段内时间，换算入口总时间均加 12 秒。

1. **虚拟地址空间，0～7 秒**：先只有父进程，逐区展开用户栈、匿名映射、堆、数据、常量与代码；代码只在相关时刻出现。
2. **独立页表，7～17 秒**：fork 后两个独立地址空间中的相同 VA 0x8000，由各自页表解释；独立页表可以暂时引用同一物理页 A=40，只读代码／常量通常也能共享。
3. **放大 COW，17～31 秒**：私有区域允许写，但当前 PTE 为只读。子写入触发保护异常，分配 B、复制整页，完成后才改变子映射，重试写入 400；父 A 仍为 40，父 PTE 不自动改成可写。
4. **显式共享，31～41 秒**：MAP_SHARED 始终指向同一页 S；子写 500，父经管道同步后读到 500。切换镜头不代表 A/B 被释放。
5. **内核记录，41～49 秒**：同一个 OS 中两个 task、mm、用户页表和各自内核栈／保存上下文；不是两份内核，也不是逐字节布局。
6. **代码与结果，49～57 秒**：按活动代码行对照私有值隔离与共享值可见；完整可运行程序通过页面底部链接查看。
7. **独立与共享，57～64 秒**：保留实际引用关系收束：同虚拟地址不保证同物理页，地址空间独立也不要求所有物理页独占。

连续衔接回改后，原物理页A从页表镜头直接平移到COW近景；共享页S写成500后保留在内核记录旁，再重排到结果与总结，不清空后复制重建。A、B、S仍是三个不同机制对象，不拿同一个节点改名冒充。原76秒和数据提交时刻不变。

采用独立构图、进入／操作／理解停留／退出，复制过程与状态提交分离。不要把完整代码、所有虚拟区域、页表与 OS 字段同时塞进一屏。

## OS 视角下，“独立”和“共享”分别是什么

```text
同一个 OS 内核中的数据（物理上也在 RAM 中，不按本图连续排列）

父 task_struct                        子 task_struct
  PID = 101                             PID = 202，PPID = 101
  mm ──→ mm_struct P                    mm ──→ mm_struct C
           pgd ──→ 用户页表 P                     pgd ──→ 用户页表 C
  内核栈 P、保存上下文 P                 内核栈 C、保存上下文 C
                    \                  /
                     可引用共同的物理页
```

- 普通 `fork` 不让父子共用同一个 `mm_struct`；两个任务的内核栈也不是同一个。内核栈与前一镜头中的**用户栈**不同。
- 独立页表不要求所有物理页立刻复制；只读代码／常量通常可以共享，私有可写页可借助 COW 延迟复制。
- COW 中的“只读”是暂时的**硬件页表写保护**。虚拟区域本身允许写，内核才能将这个合法写入处理为 COW，而非直接报非法访问。父的旧页表项不必因子换页而立即自动变成可写。
- “两个进程”不等于“两份 OS 内核”；任务记录、地址空间描述和页表是由同一个内核管理的数据。
- 文件描述符／打开文件对象等也有自己的继承与共享规则，本动画未展开；不能据“内存私有”推断所有内核资源都私有。

## 观察范围与模型边界

- 当前动画 PID、六类读值与标注的实机 VA 来自 GDB；短 VA `0x8000`/`0xA000`、物理页 A/B/S 和内核对象仍是机制模型。文中 ASCII 示意的 101／202 也只是符号示例，不是当前采集 PID。布局不按比例，不能把模型页号当 PFN。
- 动画按 4 KiB 页举例；C 程序用 `sysconf(_SC_PAGESIZE)` 取得实际页大小，分别映射一页。复制以页为单位，不是只复制一个 `int`，也不是复制整份进程 RAM。
- `.data` 和 `.bss` 可以处于同一可写映射／物理页中；`malloc` 的实现也不保证所有对象都来自传统 `[heap]` 区域。图按逻辑用途分类，不承诺固定布局。
- `/proc/self/maps` 显示虚拟区域及区域权限。`rw-p` 的 `p` 表示私有映射，**不证明物理页独占**；fork 后 COW 页的区域仍可显示 `rw-p`，硬件页表项却暂时不可写。`rw-s` 的 `s` 表示共享映射。
- 输出的相同虚拟地址和隔离数值证明地址空间语义，**不是物理页共享／COW 发生次数的直接测量**。本例不读取受权限限制的 PFN，不要求关闭 ASLR、安全防护或使用 root。
- 真实运行中，库函数、栈等其他私有页可能更早发生 COW；动画只放大选定匿名页的普通 Linux fork/COW 路径，简化了 TLB 维护、多级页表、内核映射隔离、巨页、换页与调度。共享页只有一个写者，管道负责确定读取顺序；不是通用并发读写示范。
- Linux 单线程进程示例；不将其直接推广到多线程 fork 后随意调用库函数的场景，也不把此插播任务视为 9-3 全部交互规划已完成。
- 当前为 HTML 模块页面，通过 HTTP 或静态网站观看；img 与 GitHub README 的图片预览不能承载这些网页交互。
