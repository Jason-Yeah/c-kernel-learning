# 从真实 C 程序到动画

## 用户澄清后的当前状态

此前只有 3-1 栈帧真实采集，其他主题主要是教学模型，确实不满足“多数章节有对应程序和 GDB 实际结果”。本轮已为全部七个现有主题提供配套 C 程序和真实调试证据，而不只是附加几行代码。

新增六份受控 C 实验、共用 GDB 采集器、校验器、实际源码／观测镜头和可选择停点的实验工作台；既有 stack-call 逐指令链路继续保留。导演方案见 [experiment-programs.md](experiment-programs.md)，重现步骤与限制见 [实验说明](../experiments/README.md)。

## 已完成链路

`experiments/*.c` → GCC 实际 ELF → GDB 断点／单步／多进程与信号 → `traces/*.json` 与原始命令文本 → 数据验证 → 程序／调试镜头 + 机制动画 → 独立原始 JSON／浏览器核对。

- 15 次实际运行、193 个停点：stack-call 31 个逐指令停点，六个补充主题 162 个断点／信号停点。
- 每个程序记录完整源码与 ELF SHA-256、工具版本、完整编译参数、架构、ASLR、采样时间；保留原始命令及输出。
- 全部动画可查看完整 C 程序和实际 GDB 结果。新增接入的六片有独立“C 程序与 GDB”镜头，实验台可选择运行、停点并定位对应讲解；原 3-1 仍全程真实数据驱动。
- 主画面省略采集标记／注释，但源句、行号不另造；完整实验源不删改。网页是离线回放，不是浏览器实时运行 GDB。
- 缺记录或不变量失败必须报错；source hash、字节／寄存器／信号、实际 PID 和读值有独立验证，不靠另一个手写常量自洽。

## 解释性边界不能隐藏

- 后五片标为“C／GDB 实验 + 机制模型”，并按当前镜头切换 GDB CAPTURE / MECHANISM MODEL。不能给一片有 C 程序就声称所有内部硬件／内核状态都实测了。
- Cache tag／LRU／HIT、TLB、PFN、PTE 细节、COW 物理复制与调度令牌不是普通 GDB 直接提供的数据。对应模型的短地址／页号、4×2×8B 或 64B 参数明确保留模型身份，不换成长随机数假装测量。
- 同 VA／maps 不能证明物理同页。匿名冷页首次读取可能使用共享零页，present 的变化不能证明已分配新私有页。
- 缓冲区越界为 C 未定义行为，只解释该 ELF 的实际过程。AD DE 00 改低字节，真实返回目标保留高位，不能继续用旧模型 0xDEAD 冒充。
- 递归画面八帧是压缩，不是实测上限；有终止条件的正常返回是另一次运行。GDB 陷阱、调度和真实 CPU 耗时未画成教学速度。
