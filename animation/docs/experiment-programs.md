# 七主题：先运行 C，再用 GDB 证据讲动画

本文件保留原七片实验方案。后续独立分镜见[OS基础](os-basics-storyboards.md)、[指令周期](instruction-cycle-storyboards.md)、[字节序与跨镜头保留](byte-order-storyboards.md)、[C位运算与整数](integer-bits-storyboards.md)、[第8章异常控制流](control-flow-storyboards.md)；当前全站状态见[spec](spec.md)。

## 用户澄清与本轮范围

用户要的是多数章节有完整 C 程序和实际 GDB 调试结果，不是给抽象动画贴几行示意代码。本轮为现有七个主题建立对应的可运行实验、编译／采集入口、原始调试记录及画面入口。保留纯黑、白字、大标签、源／目标分区及原有机制运动，不扩展新章。

执行顺序：本方案与分镜 → 安全、独立的小实验 → 实际 GDB 采集 → 不变量验证 → 程序／调试镜头与动画数据连接 → 实际浏览器回归。本方案先于实现写下；当前七主题 C／GDB 接入、工作台与完整播放已完成，实际结果见 [spec.md](spec.md) 和 [verification.md](verification.md)。

## 实验与证据清单

| 主题 | 对应 C 程序 | 实际观察 | 必须保留的边界 |
| --- | --- | --- | --- |
| 调用与栈帧 | stack-call.c，已有 | call/ret、寄存器、返回地址、栈字节、变量 | 已有实测链路继续保留 |
| 栈缓冲区越界 | buffer-copy.c，新增 | input／buf 的真实地址，8／9／27 次写入，保存 rbp／返回地址所在槽的实际内容，最终 SIGSEGV | 显式逐字节复制而非声称 glibc strcpy 按字节实现；越界是 C 未定义行为，只解释本次编译与运行 |
| 栈耗尽 | stack-recursion.c，新增 | 每层实际 rsp、frame 大小、进程栈上限、SIGSEGV 停点／回溯；另一次有终止条件的正常返回 | 只画部分帧时明确压缩；正常返回是独立运行，不能假装溢出后自动恢复 |
| Cache | cache-access.c，新增 | 实际数组地址、8 次读取偏移／字节、寄存器与完整数组内容 | GDB 不显示真实 Cache tag／LRU／HIT；已有 4×2×8B 是明确的机制模型，以同一 C 读取序列驱动 |
| 进程生命周期 | process-lifecycle.c，新增 | 真实 fork 返回值／PID、exec 前后同 PID、PC／CP 输出、Z 状态、waitpid 返回与 0x0700 | 两次受管道约束的调度，不穷举调度；GDB 的多进程调试不是硬件同时执行证明 |
| fork 内存 | fork-memory.c，新增；保留用户已有 demo | 父子同 VA，data／bss／local／heap／私有映射的实际隔离，shared 50→500、maps 与管道顺序 | 不把 VA 或 maps 说成 PFN／物理共享直接证据；COW 页复制／PTE 仍为标注的机制解释 |
| 地址翻译 | vm-access.c，新增 | 实际 mmap 地址／页大小、访问值、驻留位前后、只读保护与未映射 SIGSEGV／si_addr | 不能由普通 GDB 推出 TLB 命中、真实 PFN 或硬件页表全量；五条路径中相应硬件部分仍是模型 |

## 数据与呈现架构

- experiments 保存完整 C；scripts 保存固定、可审查的编译／GDB 采集器；traces 保存 JSON 和原始 GDB 文本。不得执行未经检查的任意外部代码。
- 每次发布数据记录源码／ELF SHA-256、完整编译命令、工具版本、ASLR、时间、运行参数；失败就报错，不回退到手写“预期值”。
- 每片提供完整程序与可选择停点的实际调试工作台。主动画新增独立的“程序 → 实测”镜头，不把大段终端覆盖原有运动；相关代码来自实际源码行，不另造一份简化程序冒充。
- 实测与模型并存的片子使用“C／GDB 实验 + 机制模型”身份。实验镜头显示实际地址与输出；模型镜头明确其逻辑地址／页号／Cache 参数，不把它们换成长随机数冒充实测。
- 对可直接观察的栈字节、PID、返回值等，应让主要动画数值也来自原始记录；硬件不可观测部分则明确叙述观测与解释的对应关系。
- 所有故障只在当前小实验进程中触发，禁用 core dump，限制递归栈资源，不修改系统安全配置；不运行 shellcode、攻击目标或关闭宿主系统保护。

## 验收

1. 在本机实际编译并跑完所有受控采集，保留正常退出／预期信号结果。
2. 用独立测试核对真实字节、返回地址、PID、wait 状态、读值、驻留标志、信号地址和源码哈希。
3. 浏览器直接读取原始 JSON，正反向核对动画／工作台；检查完整程序、命令、断点结果、来源和子路径资源。
4. 逐镜头检查大字不遮挡、源／目标清楚、未来数据不泄漏，并按实际时长完整播放。
5. 更新 spec、实验说明、当前数据来源身份；不能沿用上一轮“只有 3-1 实测”或把历史测试数当本轮结果。
