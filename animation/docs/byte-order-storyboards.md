# 2-1 字节序：保留同一对象的连续分镜

## 最新授权与转场规则

用户要求继续原排期第2章字节序，并明确“下一镜头需要上一镜头的内容／数据就保留，不要每次全清空”。本轮只做字节序，不提前开展补码／浮点；旧14片不改教学数据与时长。

新片96s／6个分镜。共享播放器增加可选的跨分镜持久层：同一DOM中的word数值、&word、字节内存，以及后续BE数组在需要的整个区间持续存在；分镜切换只改变标题／说明等局部内容，保留的对象沿同一主时间线移动和重排，不用复制节点冒充保留。旧的独立场景门控仍防止未来步骤提前泄露；持久层不表示把未来所有数据都显示。

需保留：word数值与地址从第1镜头出现后一直保留；位权分组在2→3保留；实际word内存从3出现后保留到结束；BE数组从4出现后保留到结束。可以退出：已不再需要的源代码、probe_byte临时读值、位权分组和中间误读结果。禁止整屏淡出到黑色再重新出现。

## 实验

完整安全C以 uint32_t word=0x12345678 为统一源；unsigned char* view合法读取对象表示，4次实际读值进入probe_byte，word不改变。独立be_encoded[4]明确初始化CC，由移位逐字节写入12/34/56/78；这是同一台x86上的**显式BE编码数组**，不是CPU切换成大端。

分别memcpy从word读出native_read、从BE数组按本机序读出raw_read，再显式按BE规则还原decoded_be；每个步骤有独立GDB停点。记录同一个word地址、原始内存、每个BE写入前后、三种读值、实际寄存器、源码行和原样命令，继续执行至成功退出。保存源码／ELF SHA、工具／参数／ASLR；不修改宿主保护，不执行陌生代码。当前Linux x86-64小端为实测，其他架构存储习惯不冒充本次测量。
