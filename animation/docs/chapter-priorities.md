## 推荐先做什么

建议第一批按 **3 → 8 → 9** 补当前关键缺口：

1. **第3章：条件跳转与循环。** 同一完整C函数，先看条件值，再看cmp／条件码／跳转、循环回边与退出；保留变量、指令位置和已形成的数据，避免再次从栈溢出专题起步。
2. **第3章：数组／指针／结构体寻址。** 用实际对象与指令把“索引／偏移／地址／解引用”区分开，为Cache和虚拟内存打底；不把数组直接说成指针变量。
3. **第8章：系统调用、异常入口与上下文切换。** 明确三者不是同一件事：一次系统调用不必切换进程，普通函数调用也不是进入内核；信号另成独立主题。
4. **第9章：多级页表。** 从现有单级解释扩展，保留页内偏移与访问权限，再补COW深入和动态分配；不要重做相同的首次缺页／fork介绍。

之后再按 **7（链接深入）→ 6（局部性）→ 10（I/O）→ 12（并发）** 推进。这里是结合已完成基础后的制作收益顺序，不是唯一阅读顺序。若目标转向服务器，10／11／12应前移；若目标转向性能或CPU设计，6／5或4应前移。

## 实验与动画边界

- 第3／7章最适合用完整C、实际GDB／反汇编／ELF直接驱动画面；优化后指令与源码不一一对应时要明确说明，不能依赖失效的DWARF局部变量。
- 第8／9章的实际系统调用参数、返回、映射和信号可以观察，但调度、真实页表／PFN、TLB和内核内部不能仅凭普通GDB冒充实测；保留可观测事实与机制解释的界线。
- 第6章访问地址和数据可实测；Cache状态仍需明确是模型。计时要说明重复次数、噪声与环境，不把一条GDB停顿当成访问耗时。
- 第12章不能执行含非原子数据竞争的C程序，再把偶然的“丢更新”当成C保证的行为；用有定义的原子操作／受控交错解释问题，再比较锁保护的完整操作。
- 继续沿用同一可逆时钟、仍需使用的同DOM对象／数据跨镜头保留、固定容量、未来隐藏和真实浏览器运动检查。新主题仍先写专门分镜，再实现与实际采集。
