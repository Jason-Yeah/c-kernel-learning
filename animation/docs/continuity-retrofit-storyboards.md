# 已有14片：连续衔接回改分镜（先于实现）

## 授权与不变项

用户要求把之前作品中适合的段落同步改为连续衔接。本轮不制作补码等新主题，不重采已验证C，不改15部的时长、94个镜头、GDB停点或已批准的递归30秒机制段。

逐片审查后，保留适合的同一对象；独立输入、独立exec、其他函数探针、访存对照不能伪装为上一次程序状态自动恢复。字节序已有共享对象，不重做；递归原机制已有匹配镜头运动，不为技术统一破坏已确认节奏，其故障→正常返回继续明确为独立运行。

## 共享实现约束

旧构图里的重复组件改为一个真实DOM对象，原本对应下一镜头的组件仅提供布局／状态描述，挂接后不保留第二份可见副本。不在onUpdate中复制整块HTML，不靠克隆截图维持画面；原局部动画仍指向同一对象的子节点。全部移动、局部状态提交、出现／退场仍在同一个可逆GSAP时钟中。

采用声明式actorContinuity：指定真实语义组、原选择器和适用镜头。按组件类型校验；寄存器、页、文件、进程窗口、Cache行和竖向数组有明确字段，不做任意HTML模糊匹配。数组按稳定key保留同一行，局部放大只移走不需要的行；不能把已知值重新抹成占位符。旧选择器通过无布局别名继续指向同一实际组件，测试和实验定位不丢失。未来对象仍隐藏。

转场基本E/A/H/X：前镜头的有效主体保持至末端（不随camera整屏淡出）；新镜头0–1.1s在空出来的通道移动／重排，必要时先横后纵；未用的局部先退，新说明在主体到位后出现，原主要操作及提交时刻不动；下一镜头H继续保留。需要独立案例时只保留硬件机制框架，不把上个案例的TLB/PTE、输出或进程地址带入。

## 已实现的使用方式

在mountFilm／mountOS／mountExperimentalFilm配置中声明actorContinuity，用shared/actor-continuity.js的actor(key, kind, members)。例如同一调用的RSP可列出caller-rsp、nested-rsp、sum-rsp、return-add-rsp、return-main-rsp对应镜头；下一视图不再创建第二份可见寄存器，而是把原节点移动到新位置。

members使用[sceneId, '#组件ID', {at, move, via}]；at默认为该镜头0（沿用原作者时间单位），move为镜头重排时间，via可指定先横后纵的避让点。Cache的before/after两个布局在原commit时刻挂到同一行，容量框不消失。竖向数组按data-memory-key重用行，保留完整VA和已知值，新对象才新入场；局部放大只折叠不用的行，绝不把父／子或虚拟／物理当同一对象。

动画代码继续使用s.$／s.$$取得真实组件；不要直接拿透明的旧选择器别名做几何测量或把它当新组件。DOM查询旧选择器的子字段仍可核对数值；真正的节点ID与切镜事件公开在film.carriedActors中。独立实验要使用不同语义组，不能只因为文字或地址偶然相同就合并。

状态补丁进入相应局部时间线，不能另在onUpdate复制DOM；首帧／未来隐藏、原有实际提交、倒拖和末帧仍由同一主时钟负责。源码／ELF／GDB身份保持不变，模型不升级为硬件实测。
